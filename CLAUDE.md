# Coding agent guide — MinecraftSiegeSurvival

This file is the canonical agent context. `AGENTS.md` is a **Git symlink** pointing here; edit this file, not the link.

## Mission and invariants

Paper 26.1+ standalone Java 25 plugin supporting Overworld, Nether, and End. Same selected zombies/skeletons/pillagers in all worlds. One active cooperative siege in an existing survival world. Players prepare without movement restrictions; once wave 1 begins, a configurable circular anchor-centered boundary applies to living participants until the game ends. Mobs hunt the living players and use the anchor only as the fallback and the spawn area. Mobs break blocks with the vanilla tool rules (bare hands on dirt and wood, a pickaxe on stone) - relaxed to bare hands on stone after `ai.desperate-after-seconds` into a wave, never for the protected blocks. They place blocks (bridges, staircases) and do all of it only inside the destruction radius. Players have one life; a final wave clear wins, all players eliminated loses.

## Commands and boundaries

- `/siege anchor`, `/siege setup`, `/siege start [waves]`, `/siege start prep [minutes] [waves]`, `/siege radius <blocks>`, `/siege status`, `/siege stop`, `/siege glow [on|off]`.
- Do not globally modify game difficulty, weather, time, game rules, or world border.
- Do not interfere with players outside the active siege except for the explicitly server-wide participation contract.
- Don't restrict players during preparation except initial teleport to initiator; on wave 1 return players from other dimensions/outside the radius to anchor.
- Use server-thread Bukkit/Paper APIs only on proper scheduler threads.
- Validate all match state changes; clean up tasks and tagged mobs on stop.
- The wave counter must reflect reality: an enemy that is really gone stops counting, an enemy that is only stored in an unloaded chunk keeps counting. Never clear a wave because a mob could not be found.
- Only blocks within the mining/destruction radius may be altered by custom AI; never break inventories, protected blocks or unknown materials.
- Player and world backups are essential. Mob-mined simple block changes use the append-only BlockJournal with best-effort reverse restoration; no blanket rollback promises.

## Source layout and design

`com.bymatej.siege`: plugin bootstrap; `game`: match state; `command`: commands and menus; `wave`: spawn and scaling; `ai`: target/mine policy; `listener`: boundary, death and world events. Avoid adding NMS unless absolutely necessary and separately version-gated.

`paper-api` is `compileOnly`, so the deterministic helpers under `ai/` (`ToolRules`, `LadderClimb`, `ProgressTracker`, `TargetPicker`, `TerrainTools`, `MiningTimes`, `AbilityGate`) and under `game/` (`WaveMath`, `MobLedger`) stay free of Bukkit types and are unit tested. Put new rules there instead of in the scheduler-heavy classes.

## Siege AI behaviour (implemented — keep this section in sync)

The mobs must feel like players. These behaviours are implemented, unit tested and live verified; do not regress them silently and document every change here **and** in the README.

- **Players first, anchor second**: the anchor is where the fortress is and where the enemies spawn; the **goal is always a player** when one is reachable. `ai/TargetPicker` (pure, unit tested) picks the target: the current one is kept while it is alive, in the same world and inside `ai.pursuit-radius`, otherwise the nearest player inside `ai.detection-radius` is taken, preferring a visible one. A player the mob **cannot see** is still hunted (`ai.require-line-of-sight: false`), so a 1x1x2 box is no safe spot - the mob digs it open. Only when no player is around does the mob walk to the anchor. A player in **another world** is never a candidate: `Location#distanceSquared` throws when the worlds differ, so the distance is only measured between players of the same world.
- **Aggressive breaching**: a mob is only "arrived" when it has a **line of sight** to its target, so mining continues until the mob can really see the player. The mining branch runs even while a target exists (it used to be skipped), and the breach planner is called with the player's position as the goal. Once a mob is breaking its way in it **keeps breaking** (`memory.breaching`): it does not wait for another stall between two blocks. The break time shrinks in the last quarter of the waves (`WaveMath.breakTimeFactor`, `mining.late-breach-speed`, 2 = twice as fast). Every planner search costs a mining slot, so the A* work stays bounded even when many mobs are stuck.
- **Doors**: every siege mob opens a closed wooden door, trapdoor or fence gate on its way to its goal — including creepers, blazes and piglin brutes, which have no vanilla door AI. Both halves of a door are opened (tall mobs would otherwise collide with the upper half). A **trapdoor is a single block** — its block data is "bisected" (top half = flat in the floor, bottom half = hanging from the ceiling), so it must not be treated like a two block door, or it is never opened at all. The search covers the block below the mob's feet and two blocks above its head, so a trapdoor in a floor or a roof is found, and the opening also runs **while the mob climbs a ladder** — a hatch over the ladder hole would otherwise stop the climb for good. Iron and copper doors are redstone parts: they stay closed, only a pickaxe breaks them. A door is only opened **inside the destruction radius**.
- **Walls**: progress is measured as the distance to the goal, so a mob that jitters against a wall counts as stuck (`ai/ProgressTracker`), starts the breach planner and mines the first breakable block in the way. The block is journaled before it is removed.
- **Tool rules** (`ai/ToolRules`, the single source of truth): bare hands break dirt and wood, a pickaxe breaks stone (cobblestone, deepslate, stone bricks…), a shovel is fastest on soil, an axe fastest on wood. Containers, tile entities, redstone, ores, metal blocks, fluids, **ladders**, scaffolding and vines are never broken. The right tool is much faster than the wrong one. Mining happens only **inside the destruction radius**. `ToolRules.canBreakDesperate` is the relaxed variant that a desperate mob uses - see below.
- **Ladders**: Paper's A* cannot climb, so the plugin steers the mobs itself — `ai/LadderClimb` (pure, unit tested) plus the per-tick `SiegeBrain.movementTick()` task. A stuck mob looks for a ladder within reach, climbs it and steps onto the platform at the top. The ladder has to reach the goal's level and the mob never leaves the arena. The door opening runs **while the mob climbs**, so a trapdoor over the ladder hole is opened instead of blocking the climb forever. Toggle: `ai.ladder-climbing`.
- **Terrain**: the ground in front of a mob is checked **every tick** in `SiegeBrain.movementTick()`, so a mob never walks into a hole. `ai/TerrainTools` (pure, unit tested) decides: a gap that is one block wide and at most one block deep is jumped (`ai.jump-over-gaps`), a wider or deeper hole is **bridged** with a cobblestone floor (`ai.building-enabled`, from `ai.bridging-from-wave-percent`, 0 = from the first wave) - a hole two blocks deep would trap the mob. A one block step is jumped right away. Paper has no jump call for mobs, so a jump is a `setVelocity` that is kept alive for a few ticks in case the mob's own AI cancels it; the sideways speed is capped (`MAX_JUMP_SPEED`), so a repeated jump cannot run away.
- **Towers**: if the goal is more than 1.5 blocks above the mob, the mob **builds itself up**: it jumps and puts a block under its own feet until it reaches the player's level. This is a late game ability (`ai.building-from-wave-percent`, 75 = the last quarter of the waves) — but a wave that runs long unlocks it as well (`ai.building-after-seconds`, 300 = five minutes into the wave, the same moment the enemies start glowing), so a player on a roof is reached in every wave. The gate is pure and unit tested (`ai/AbilityGate`). The base level of the next step is remembered, and the mob gives the pillar up when a block cannot be placed.
- **Placed blocks are journaled** like broken ones (`BlockJournal.recordPlaced`): a bridge or staircase is removed again when the match ends, but only while it is still the same block. Every placement happens inside the destruction radius and fails closed if the journal write fails. A block is never placed in mid-air (the mob has to stand on ground), in a cell a player occupies, or over anything that is not air.
- **Gear that is really used** (`SiegeGame.siegeMainHand`): zombies get an axe, a sword or a pickaxe (axe certain from wave 3), vindicators an iron axe, piglin brutes a netherite axe, wither skeletons a stone sword, skeletons a bow and pillagers a crossbow. The main hand item is both the weapon (vanilla melee damage uses its attack modifier) and the mining tool. Melee mobs may carry a shield in the off hand and raise it with `startUsingItem(OFF_HAND)` while closing in, lowering it within 3 blocks so they can still strike. Keys: `mobs.random-equipment`, `mobs.equipment-chance`, `mobs.shield-chance`.
- **Piglin brutes** never turn into zombified piglins: `PiglinAbstract#setImmuneToZombification(true)` keeps them brutes in every dimension.
- **The arena stays loaded**: `SiegeGame.holdSpawnChunks` holds **every chunk inside the combat radius** around the anchor with a plugin chunk ticket, so a mob that wanders off does not freeze in an unloaded chunk - an unloaded mob neither moves, nor glows, nor can be found. The tickets are released when the match ends.
- **No enemy gets lost**: `SiegeGame.recoverMobChunks` holds the chunk of a mob that left the loaded area (it runs every tick, not only for `/siege glow`), and `SiegeGame.rescueEndangeredMobs` brings a mob back to the anchor when it fell into the void, into lava or **outside the combat radius** - out there it is out of the players' sight and out of the server's activation range, so it would stand still forever. The spawn spot of every mob is remembered, so even a mob that was never seen after its spawn can be found.
- **The enemy counter is exact** (`game/MobLedger`, pure, unit tested): a mob stops counting when it is really gone. `EntityRemoveEvent` (cause `UNLOAD` excepted - that only stores the mob) drops it from the wave, and the tick drops a mob that cannot be found while the chunk it was last seen in is loaded. A mob that waits in an unloaded chunk still counts, so a wave is never cleared by accident. `/kill` of the admin works on siege mobs: the `KILL` damage cause is allowed through the environmental damage filter.
- **The counter rules are phrased as "the mob is gone"**, never as "the mob is alive": the tick drops the mobs for which the rule is true, so an inverted rule empties the wave one tick after it started instead of keeping the living enemies. `MobLedger.removeGone` does the dropping and is unit tested in that direction. A wave only ends when the last enemy is really gone - it never clears itself.
- **Glow**: a wave that runs long makes its enemies glow (`waves.glow-after-seconds`). `/siege glow [on|off]` forces the same glow on every siege mob on demand (toggle without an argument, usable from the console); `/siege status` shows `Glow forced|auto` and the position of the remaining enemies. The forced glow belongs to the wave it was switched on in: `SiegeGame.beginWave` clears `forceGlow` and removes the effect, so the next wave starts dark and glows on its own after five minutes (or when `/siege glow` is used again). The answer also prints the coordinates of the remaining enemies and holds the chunks of mobs that left the loaded area - a mob in an unloaded chunk neither ticks nor glows.
- **Desperate digging**: after `ai.desperate-after-seconds` (600 = ten minutes into the wave) a stuck mob digs through everything, **even stone with bare hands**. `ToolRules.canBreakDesperate` relaxes the tool rules, `MiningPolicy.mayBreak(mob, block, desperate)` keeps the valuable blocks protected (hardness limit 20) and `MiningPolicy.estimatedTicks(block, tool, desperate)` slows the bare hands break down (`ai.desperate-break-factor`). The desperation is time based, never triggered by the forced glow, so the player keeps the glow window to find the last mob himself. `0` = never, `-1` = always.
- **The breach planner** (`ai/BreachPlanner`) is a bounded ground level A*. Two rules keep it honest: the search budget (`MAX_VISITED`) has to cover the area, and the price of a broken block is capped (`ai/MiningTimes.searchCost`, 4.0). Without the cap the planner walks around a wall instead of digging through it; without the budget it never gets to the wall at all. The digging time itself is calculated in `SiegeBrain.tryMine`, not in the search.
- **Debugging**: `ai.debug-logging` logs the goal, the distance, the stall counter, the mining target and the last terrain action (`jump 1/1`, `bridge 1/2`, `step`) of every mob once per second. Use it to see why a mob goes somewhere.

## Testing priorities

1. A command-free and restarted server remain unchanged; safe startup/shutdown.
2. 1-player and multi-player state transitions and win/lose conditions.
3. Preparation is unrestricted; boundary activates exactly at first wave, for walk/teleport/vehicle/world changes; spectator safety.
4. Health starts at 30%, ends at 150%, and is properly capped for a 1-wave match.
5. Natural spawns around the anchor suppressed without altering global gamerules.
6. Correct mob registration, incremental spawning and cleanup.
7. Doors, tool eligibility, protected blocks, no mining outside the configured zone, and pathfinding under obstructed structures.
8. Ladder climbing, the gear the mobs actually use (weapon damage, mining speed, raised shield) and the piglin brute that never converts.
9. `/siege glow` switches the glow on and off for every living siege mob, prints where the remaining enemies are, and the forced glow ends with the wave it was switched on in.
10. Survival mode restoration, reconnect handling and server crash recovery.
11. Nether roof/void, cave floors and End islands: validate safe spawn elevations and never spawn into unsupported spaces.
12. Player-first targeting: a hidden player is hunted, a boxed-in player is dug out, and the anchor is only the fallback. A player in another world must never break the control tick.
13. Terrain: a one block gap is jumped without placing a block, a two block deep trench and a wider moat are bridged, a tower is climbed with placed blocks - and every placed block is journaled, never placed in mid-air and never inside a player.
14. Desperation: a fist only zombie does **not** dig through stone before `ai.desperate-after-seconds` and digs through it afterwards (the block is journaled), while the protected blocks stay intact.
15. The wave counter: a mob killed by a player, killed by `/kill` or removed by another plugin stops counting, a mob that waits in an unloaded chunk keeps counting, and a mob that left the arena is brought back to the anchor. A wave **never clears itself**: after the wave begins the counter stays at the number of spawned enemies until they really die.
16. A player on a roof: the mob breaks in, climbs the ladder, **opens the trapdoor** over the hole and reaches the player; a fence gate in the way is opened as well. After `ai.building-after-seconds` the mobs build themselves up to a player who is above them - also in the first wave.

## Development discipline

- Implement small, reviewable milestones. Do not claim features are production ready without compiling and Paper integration testing.
- Java 25 + Gradle Kotlin DSL. Default local Paper API: `26.1.2.build.74-stable`; CI also validates `26.2.build.129-stable` (the local Gradle cache holds `26.2.build.134-stable`, which builds the same code).
- Release builds pass `-PminecraftVersion=<MC>`, `-PpluginVersion=<MSS>` and `-PpaperApiVersion=<MC>.build.<N>-stable`. The JAR and release tag are both `MSS-<MC>.<MSS>`; the expanded `plugin.yml` must contain the selected versions.
- Releases are published manually using `.github/workflows/release.yml`. Never auto-publish from an ordinary push, overwrite a prior tag, or embed tokens in tracked files.
- Prefer Paper API over NMS. Do not silently disable permissions or protection integrations.
- Update README when features or limitations change; add unit tests for deterministic logic.
- Never commit secrets, tokens, private keys, world saves, local test-server directories or player-specific files. `.gitignore` is defense-in-depth, not permission to stage secrets.
